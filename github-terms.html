GitHub 高频术语表 · 45 词

一、界面上会看到的词（名词 / 按钮）

用法：白天在公司过一遍，晚上上 GitHub 操作时对照实物。

每个词都配了"记忆点"——大多数是你今晚亲手碰过的东西，看到实物想词，看到词想实物。

英文 中文 记忆点
repository（简称 repo） 仓库 你建的 my-site 就是一个 repo
README 自我介绍文件 仓库的门面，进入首页自动展示
commit 提交，一次存档 你点过三次的绿色按钮就是它
branch 分支 页面左上角的 main 就是默认分支
main 主分支（默认名） 你现在所有文件都活在它上面
fork 把别人的仓库复制一份到自己账号 你对那个 Actions 学习仓库干过
star 收藏 / 点赞 GitHub 版的"赞"
issue 问题讨论帖 项目的问题区和留言板
pull request（PR） 合并请求 "我改好了，请审查后合并进去"
settings 设置 Pages 藏在里面的那个标签
deployments 部署记录 你见过的那个绿色勾
history 提交历史 3 Commits 点进去看到的东西
profile 个人主页 你的 GitHub 名片页
owner 所有者 建仓库时第一行选的你
visibility 可见性 public / private 的选择开关
preview 预览 改 Markdown 文件时旁边那个按钮
blame 追责视图 看每行代码是谁哪次改的（名字很形象）

二、操作动作（动词）

英文 中文 记忆点
create 创建 Create repository 就是建仓库
upload 上传 你拖 html 进去的那一步
edit 编辑 文件右上角的铅笔图标
delete 删除 你准备删中文文件时用的三个点菜单
rename 重命名 中文名改 index.html 那件事
push 推送：本地 → GitHub 以后用命令行时会天天敲
pull 拉取：GitHub → 本地 和 push 方向相反
clone 克隆整个仓库到本地 第一次用命令行就会用它
merge 合并分支 把 A 分支的改动并进 B
revert 撤销某次提交 改错了的后悔药
deploy / deployment 部署：代码变成能访问的网站 Pages 干的事
publish 发布 第一次上线网站时用

三、概念词（聊技术时出现）

英文 中文 记忆点
Git 版本控制工具本身 注意：Git ≠ GitHub，前者是软件后者是网站
GitHub 托管 Git 仓库的网站 你现在注册的这个
version control 版本控制 每次 commit 都是存档，随时回退
default branch 默认分支 新仓库自动生成的那条（现在是 main）
public / private 公开 / 私有 public 才能免费挂网站
render 渲染 浏览器把源代码变成页面的过程
source code 源代码 仓库里点开 html 看到的那些
static site 静态网站 Pages 挂的就是这种，全是现成文件
URL / link 网址 / 链接 evannightweaver.github.io/my-site
domain 域名 网址的名字部分，以后可以买自己的
markdown 轻量排版语法 README.md 用的格式，# 是标题
workflow 工作流 Actions 里的自动化流程，用 yml 写
CI/CD 自动化测试+部署 Actions 干的事，第 3 层的内容
commit message 提交备注 "Add files via upload" 那句话，建议自己写清楚
local / remote 本地 / 远程 你的电脑 / GitHub 服务器
